# v6-20260708 数据结构草案

v6 先不兼容旧版本，目标是让静态分发、搜索、编辑和后续数据迁移更清楚。

## 设计原则

1. 使用稳定 `id` 标识一个卫生间点位，不再依赖文件名或时间戳。
2. 用 `null` 表达未知，避免 `undefined`、缺字段、空对象混用。
3. 把“卫生间类型”“进入限制”“设施能力”“无障碍信息”拆开表达。
4. 图片、评论、外部来源标识作为附属数据，不塞进主字段语义里。
5. 支持按区域静态分片，通过 manifest 让浏览器按需下载和缓存。

## 核心对象

```ts
interface ToiletPlace {

```

## 静态分发

推荐使用 `manifest.json` 描述区域分片：

```json
{
  "version": "20260708",
  "generatedAt": 1783497600000,
  "regions": [
    {
      "id": "cn-shanghai",
      "name": "上海",
      "bbox": [120.85, 30.67, 122.12, 31.88],
      "updatedAt": 1783497600000,
      "recordCount": 120,
      "dataUrl": "./regions/cn-shanghai.json",
      "sha256": "..."
    }
  ]
}
```

浏览器可以先读取 manifest，再按地图视野或用户选择下载区域数据，并写入 IndexedDB/Cache Storage。
